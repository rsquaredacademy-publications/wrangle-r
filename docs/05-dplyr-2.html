5.4 Specifying keys with join_by()

Every join below matches rows on the id column present in both tables, written as by = join_by(id). Use join_by() (dplyr >= 1.1) instead of a plain string whenever keys need attention:

  • same name in both tables: by = join_by(id)
  • different names: by = join_by(customer_id == id)
  • multiple keys: by = join_by(id, region)
TipAudit habit

Before trusting any join, run anti_join() in both directions (see Anti Join). Rows on either side with no match are data-quality findings, not join errors — investigate them first.

5.5 Inner Join

Inner join return all rows from Age where there are matching values in Height, and all columns from Age and Height. If there are multiple matches between Age and Height, all combination of the matches are returned.

5.9 Semi Join

Semi join return all rows from Age where there are matching values in Height, keeping just columns from Age. A semi join differs from an inner join because an inner join will return one row of Age for each matching row of Height, where a semi join will never duplicate rows of Age.

5.9.1 Case Study: Details of customers who have placed orders

To get customer data for all orders where customer data exists, let us join the order data with the customer data using semi_join. You can observe that data is returned only for those cases where customer data is present.

Those 245 rows are a data-quality finding (missing or mismatched customer data upstream), not a join mistake: an inner_join() will silently drop them, and a left_join()/right_join() will carry them with NAs. Decide deliberately which behavior the analysis needs.

5.11 semi_join vs anti_join: which filter join to use?

semi_join() and anti_join() are filter joins: they filter rows of x by match status in y and never add columns from y.

Question Filter join
Which customers placed orders? (keep matches) semi_join(customer, order, by = join_by(id))
Which customers placed no orders? (keep misses) anti_join(customer, order, by = join_by(id))
Which orders have no customer record? (audit the other side) anti_join(order, customer, by = join_by(id))

5.11.1 When to use semi_join instead of inner_join

Use semi_join() when you want the customers (or orders) themselves, not the combined rows. An inner_join() duplicates the left row once per match — here 42 customers with orders explode to 55 joined rows — while semi_join() returns each matching customer exactly once (42 rows, customer columns only):

5.13 Cross Join

cross_join() returns every combination of rows from both tables (a Cartesian product), so it takes no key. Use it for grids — e.g. all size × color combinations — never for large tables, since the result has nrow(x) * nrow(y) rows.

cross_join(tibble(size = c("S", "M")), tibble(color = c("red", "blue")))
# A tibble: 4 × 2
  size  color
  <chr> <chr>
1 S     red  
2 S     blue 
3 M     red  
4 M     blue

## semi_join vs anti_join: which filter join to use?

`semi_join()` and `anti_join()` are *filter* joins: they filter rows of `x`
by match status in `y` and never add columns from `y`.

| Question | Filter join |
|---|---|
| Which customers placed orders? (keep matches) | `semi_join(customer, order, by = join_by(id))` |
| Which customers placed no orders? (keep misses) | `anti_join(customer, order, by = join_by(id))` |
| Which orders have no customer record? (audit the other side) | `anti_join(order, customer, by = join_by(id))` |

### When to use semi_join instead of inner_join

Use `semi_join()` when you want the *customers* (or *orders*) themselves, not
the combined rows. An `inner_join()` duplicates the left row once per match —
here 42 customers with orders explode to 55 joined rows — while `semi_join()`
returns each matching customer exactly once (42 rows, customer columns only):

```{r dplyr_semi_vs_inner}
# one row per customer with orders — no duplication, no order columns
semi_join(customer, order, by = join_by(id))

# one row per order — customers repeat, order columns attached
inner_join(customer, order, by = join_by(id))
```

Rule of thumb: filtering rows → `semi_join()` / `anti_join()`; combining
columns → `inner_join()` / `left_join()` / `full_join()`; diagnosing coverage
→ `anti_join()` in both directions.
